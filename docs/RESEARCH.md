# SpeakingT 기술 조사와 검증 설계

조사 기준일: 2026-10-27 (Asia/Seoul). 공식 문서, 데이터 배포자, 원논문을 확인했다. 아래의 **설계 제안과 합격 기준은 이 프로젝트를 위한 제안**이며, 아직 수행한 실험 결과가 아니다.

## 1. 실현 가능성과 목표 정의

개인 영어 말하기 튜터는 실현 가능하다. 다만 원어민 녹음 수십억 개로 음성 기반 모델을 처음부터 학습하는 것은 첫 단계에 필요하지 않다. 이미 학습된 음성 표현 모델을 사용하고, 학습자 음성에 대한 사람의 평가로 작은 평가 모델을 보정하는 접근이 현실적이다. 한국인 영어 학습 아동과 SpeechOcean762를 대상으로 사전 학습된 wav2vec 2.0/HuBERT 표현을 활용한 발음 평가 연구도 있다. 이 연구가 한국 성인 개인에게 같은 성능을 보장하지는 않는다. [Kim 외, Interspeech 2022](https://www.isca-archive.org/interspeech_2022/kim22k_interspeech.pdf)

사용자가 말한 “정답 발음”은 **목표 발음(target pronunciation)**, **참조 발음(reference pronunciation)** 또는 사전상의 **대표 발음(canonical pronunciation)**이라고 부를 수 있다. 프로젝트에서는 미국 영어를 학습 목표로 삼되, 모든 미국 화자에게 하나의 정답 억양이 있다고 가정하지 않는다. 질문, 강조할 단어, 감정, 대화와 발표의 차이를 함께 고려한다.

평가 목표도 구분한다. 듣는 사람이 실제로 알아들은 정도(intelligibility), 이해하기 쉬운 정도(comprehensibility), 선택한 미국 영어 억양과의 유사도는 동일한 수치가 아니다. 학습 효과 검증에서는 이들을 섞어 하나의 “원어민 점수”로 만들지 않는다. [Saito·Trofimovich·Isaacs의 검증 연구](https://discovery.ucl.ac.uk/id/eprint/1525578/)

## 2. 권장 분석 구조

```text
원본 음성 + 선택적 읽기 문장
  → 음질 확인(클리핑·지나치게 작은 음량·잡음)
  → 발화 구간 + 시간 정보
  ├─ 전사/사용자 수정 → 단어·음소 시간 정렬 → 발음 평가
  ├─ 음성의 F0·에너지·길이 → 강세·리듬·억양 분석
  └─ 원본 음성 + 축어 전사 → 머뭇거림·반복·수정·한국어 후보
  → 근거 구간·불확실성·재생 위치를 포함한 구조화 결과
  → 한국어 피드백 + 한두 가지 재연습 과제
```

- **읽기부터 시작한다.** 정해진 문장에서는 예상 단어가 있으므로 위치를 찾고 오류를 확인하기 쉽다. 자유 발화는 별도 모드로 확장한다. 자유 발화의 인식 결과를 정답 문장으로 재사용하면 ASR이 놓친 단어가 평가에서도 사라질 수 있으므로 사용자가 전사를 수정할 수 있어야 한다.
- **음소 정렬과 채점을 구분한다.** Forced alignment는 주어진 글과 음성을 시간상 연결한다. Montreal Forced Aligner는 음성, 전사, 발음 사전, 음향 모델을 이용하는 후보 도구이다. 정렬이 되었다는 사실만으로 발음이 정확하다고 판정하지 않는다. [MFA 공식 문서](https://montreal-forced-aligner.readthedocs.io/en/v3.3.7/user_guide/workflows/alignment.html)
- **음소 평가는 기존 기법을 기준선으로 삼는다.** GOP(Goodness of Pronunciation)는 기대 음소와 음향 모델의 증거를 비교하는 계열의 점수다. Kaldi에 공개 레시피가 있다. 모델 확률을 곧바로 사람의 발음 점수로 해석하지 않고 학습자 라벨로 보정한다. [Kaldi 공식 GOP 설명](https://github.com/kaldi-asr/kaldi/blob/master/egs/gop_speechocean762/README.md)
- **주파수 분석은 관측 수단이다.** 전체 파일의 FFT 차이만으로 발음 오류 위치나 억양의 적절성을 판정할 수 없다. 짧은 시간 구간의 스펙트럼, F0, 강도, 음절/단어 길이와 언어적 위치가 필요하다. 예를 들어 pYIN은 F0와 유성 여부·확률을 제공한다. 유성 구간이 아닌 곳에 억지로 음높이를 채우지 않는다. [librosa pYIN 공식 문서](https://librosa.org/doc/0.11.0/generated/librosa.pyin.html)
- **음높이의 절댓값이 아니라 변화도 확인한다.** 화자별 중심 음높이에 대한 반음(semitone) 변화와 정렬된 강세·길이 패턴을 함께 비교하는 방식을 제안한다. 같은 문장을 다른 의도로 읽은 참조를 무조건 정답으로 사용하지 않는다. 시간 정렬/DTW로 얻은 유사도도 설명 보조 자료이며 검증 전에는 발음 정확도 점수가 아니다.
- **무음과 “um”은 다르다.** VAD나 에너지 문턱값은 무음 후보를 찾을 수 있으나 반복, 한국어, 의미 없는 발언을 판정하지 못한다. 축어 전사(verbatim transcription)와 별도 음성 이벤트 분류가 필요하다. 전사에서는 비유창성이 사라질 수 있고, 이를 보존하는 레이블 설계가 별도 연구 주제다. [Mihajlik 외, Interspeech 2024](https://www.isca-archive.org/interspeech_2024/mihajlik24_interspeech.html)
- **피드백은 관측값에서 출발한다.** 예: “3.2–4.1초에 긴 중단이 관찰됨”, “이 단어의 음소 후보가 불확실함”. 필러를 모두 잘못으로 처리하지 않으며, 한국어 전환은 학습 목표에 따른 별도 항목으로 기록한다. “이상한 발언”은 발음·문법·문맥 관련성 중 무엇인지 나누어야 한다.

## 4. 빠른 실제 발음 평가 기준선: 선택적 외부 서비스

Azure Pronunciation Assessment는 읽기(scripted)와 자유 발화(unscripted) 평가를 지원한다. 음소/단어 정확도, 유창성 등을 반환하며 prosody 평가는 현재 `en-US`에 한정된다. 30초를 넘는 파일은 continuous mode가 필요하고, 이 모드에서는 `EnableMiscue`를 사용할 수 없어 누락/삽입을 별도 비교해야 한다. [Microsoft 공식 구현 문서](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment)

Prosody는 기본 음성 인식 요금과 별도 과금 항목이다. [Microsoft 공식 도구·가격 설명](https://learn.microsoft.com/azure/ai-services/speech-service/pronunciation-assessment-tool)

설계 제안: 이 서비스를 선택적 어댑터로 제공하면 로컬 측정 도구와 전문 평가를 비교할 수 있다. 외부 서비스 점수는 `provider`와 함께 보존하고 로컬에서 학습한 점수로 표시하지 않는다. API 키는 환경변수에 두고 GitHub에 저장하지 않는다. 음성을 보내는 동작은 명시적인 서비스 사용 선택에 연결한다. 외부 점수도 한국 사용자에 대한 오탐률과 반복 안정성을 직접 확인해야 한다.

## 5. 학습과 평가 계획

1. **평가 데이터를 먼저 고정한다.** 서로 다른 날 녹음한 읽기·짧은 자유 발화와 다양한 음질을 포함한다. 사용자의 마지막 평가용 녹음은 학습에 사용하지 않는다. 새 사용자 일반화 평가는 화자를 분리하고, 문장 암기 여부는 별도의 미관측 문장 평가로 확인한다.
2. **한국어 화자 수가 적다는 점을 반영한다.** L2-ARCTIC 한국어 4명은 leave-one-speaker-out 등 제한된 실험에 활용할 수 있으나, 높은 점수가 나와도 넓은 일반화를 주장하지 않는다. 전체 L1·성별·음질 조건의 결과와 한국어 부분집합 결과를 따로 보고한다.
3. **서로 다른 기준선을 비교한다.** 사람의 평균/단순 예측, 음향 특징 기반 작은 모델, GOP, 사전 학습 encoder를 고정한 평가 head, 필요한 경우 제한된 fine-tuning 순서로 진행한다. 변경점 하나씩 비교해 무엇이 효과적인지 확인한다.
4. **epoch 수 대신 검증 성능으로 선택한다.** 상한 epoch, early stopping, validation metric, seed, 체크포인트 정책을 기록한다. 최적 validation checkpoint만 선택하고 test set은 최종 비교에 사용한다. 학습 손실만 낮아지는 장기 반복은 강건성의 증거가 아니다.
5. **지표를 기능별로 분리한다.** 점수: MAE와 Pearson/Spearman 상관. 오류 검출: precision/recall/F1과 오경보율. 시간 위치: 사람이 표시한 구간과의 오차/겹침. 정렬 실패·음질 불량: 실패율과 보류율. 개선 효과: 연습 전후 블라인드 청취 평가.
6. **불확실하면 보류한다.** 짧은 발화, 낮은 음질, 불확실한 전사·정렬에는 확정 발음 조언을 생성하지 않는다. 평가자가 들은 실제 오류와 모델이 찾은 오류가 맞는지를 확인한다. ASR WER 감소만으로 학습 효과가 입증되지는 않는다.

GOP·음소 평가·운율 평가에는 서로 다른 가정과 한계가 있다. 분야 전체의 과제 정리는 [El Kheir 외, EMNLP 2023](https://aclanthology.org/2023.findings-emnlp.557/)를 참조한다. 비유창성의 음성 기반 검출과 타임스탬프 검증에는 [FluencyBank Timestamped 원논문](https://pubs.asha.org/doi/10.1044/2024_JSLHR-24-00070)이 참고가 된다. 해당 데이터는 말더듬 화자를 포함하므로 영어 학습자의 망설임과 그대로 동일시하지 않는다.

## 6. 제안하는 초기 성공 기준

다음 숫자는 개발용 목표이며 현재 달성 결과가 아니다. 실제 데이터 수와 사람 평가의 일치도를 보고 조정한다.

- 읽기 20–30문장과 자유 발화 3–5개를 여러 날에 걸쳐 수집하고, 분석할 소수의 문장에는 최소 2명의 독립 평가를 확보한다. 이는 개인 파일럿이며 통계적으로 강한 제품 성능 보증은 아니다.
- 사람이 확인한 오류를 대상으로 “우선 교정할 항목”의 precision 0.80 이상을 초기 목표로 삼는다. recall과 평가 구간 수를 함께 공개해 적게 지적하는 방식의 수치 부풀리기를 막는다.
- 동일 파일 재분석은 설정·버전이 같을 때 재현되어야 한다. 여러 번 재녹음한 동일 문장은 모델 불안정성과 실제 발음 차이를 분리해 살핀다.
- 1–2주 연습 전후에는 연습하지 않은 문장도 포함하고, 순서를 가린 청취 평가에서 이해 용이성 및 목표 오류의 개선 여부를 확인한다. 점수 상승만으로 학습 성공을 선언하지 않는다.
- 녹음 재생 → 문제가 있는 시간대 확인 → 구체적 한 가지 교정 → 재녹음의 반복을 사용자가 실제로 끝낼 수 있어야 한다.

## 7. 현재 문서가 증명하는 범위

이 문서는 설계와 출처 조사다. 모델 다운로드, 대규모 음성 수집, fine-tuning 완료, 원어민 수준 판정 정확도 또는 사용자 음성 평가 성공을 증명하지 않는다. 구현은 각 기능을 `관측값`, `규칙 기반 후보`, `외부 평가 결과`, `검증된 학습 모델` 중 어느 단계인지 드러내야 한다. 로컬 음량·무음·음높이 측정이 가능하다는 이유만으로 발음 교정 모델이 완성되었다고 표현하지 않는다.
